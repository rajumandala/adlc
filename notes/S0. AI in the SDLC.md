# S0. AI in the SDLC

## What this part is

The main course built an **AI order assistant inside a broker's trading app**. It ended on one rule: the model proposes, code decides. Every control, from `check_order` to the evals, is code.

This part asks who writes that code. At the broker, more and more of it is written, reviewed and tested by AI. A developer asks an assistant for a fix. A coding agent opens pull requests by itself. An AI writes the tests that are meant to catch mistakes. Each of these is a new way for a bad change to reach the controls the course built.

The example stays the same. The same assistant, the same `check_order`, `get_quote` and `MAX_ORDER_VALUE`, the same evals from [note 05](https://github.com/rajumandala/aisec-notes/blob/main/05.%20Evaluations.md). What changes is the attacker's target: not the running assistant, but the team building it.

## How the notes are built

Each note follows the pattern of the main course:

1. **It starts from the previous problem.** The first note starts where [note 15](https://github.com/rajumandala/aisec-notes/blob/main/15.%20Governance.md) ended.
2. **It adds one way AI is used in building the assistant.**
3. **It shows the security point with an example change to the assistant's code.** The code in this part has not been run; each note says what would happen.
4. **It names the OWASP risks** in a short table: example, issue, fix.
5. **It ends on the next problem** and links to the note that solves it.
