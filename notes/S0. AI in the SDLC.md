# S0. AI in the SDLC

## What this part is

The main course built an AI order assistant inside a broker's trading app. Its controls were all code: `check_order`, the pinned vendor tools, the guardrails, the evals.

This part is about how that code gets written. At the broker, developers use AI assistants to write fixes, coding agents to pick up issues and open pull requests, and AI to write tests and evals. Each of these can let a bad change into the controls the course built. An attacker who cannot fool the assistant may find it easier to fool the tools the team uses to build it.

The example stays the same: the same assistant, the same `check_order`, `get_quote` and `MAX_ORDER_VALUE`, and the same evals from [note 05](https://github.com/rajumandala/aisec-notes/blob/main/05.%20Evaluations.md).

## How the notes are built

The notes follow the same pattern as the main course:

1. Each note starts from the problem the previous one ended on. S1 starts where [note 15](https://github.com/rajumandala/aisec-notes/blob/main/15.%20Governance.md) ended.
2. It covers one way the team uses AI to build the assistant.
3. It shows the security point with an example change to the assistant's code. None of the code in this part has been run, and each note says so.
4. It lists the OWASP risks it meets, each with an example, the issue and the fix.
5. It ends on the next problem and links to the note that deals with it.
